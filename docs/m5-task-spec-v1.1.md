## 2. 列表按最外层列表项分块

替换v1“整段连续列表作为一个块”的规定：

1. 一段列表中，每个**最外层列表项**单独成块，支持无序和有序列表标记。块包含该项的首行、续段、缩进公式、完整围栏代码及嵌套子列表，直到下一个同层列表项或列表结束。
2. 保留原标记、缩进和字符；不把列表项重写成标题，不反缩进。只改变引用的原文范围。项目间分隔空白另存于来源/分块清单，以便核对覆盖。
3. 不按嵌套子项、项内空行、公式内部空行或代码中的伪列表标记继续拆分。本版只人工核定小批边界，不交付通用Markdown解析器。
4. 单个列表项若明确引入两个或更多独立结构角色，例如 `Thm` 陈述后紧接 `Pf` 证明，则为 `uncertain`、`reason=mixed_roles`。缩进并不消除这两个角色；本版不继续把同项定理与证明拆开。
5. “证明见后文”等正文引用不算独立证明引入；引用/代码内标记仍不生效。列表项没有活动角色标记时仍为 `body`，不凭数学内容猜类别。

例如，一项Definition、一项Thm含Pf、一项Ex会产生三个块，分别是definition、uncertain/mixed_roles、example。
这里的uncertain是**单块确实包含多个角色**，不是标注者尚未写清规则。所有块仍须逐项输出，不能丢弃混合块。

## 3. 补充英文缩写

除v1完整标记外，增加以下明确映射，英文忽略大小写：

| 标记 | 类别 |
| --- | --- |
| `Thm` | `theorem` |
| `Pf` | `proof` |
| `Ex` | `example` |

标记可出现在块首，外面可有ATX标题、列表标记、编号或粗体；标记后允许常规标点（含缩写后的句点），须是完整单词，`Explain`不因开头含Ex就成为例子。
同一列表项内独立的续段角色标记也参与混合角色判断。只提及缩写而没有引入该角色内容不改变类别。
本版没有额外开放任意英文缩写或主题标签，`Def/Prop/Cor`等未列形式不自行扩展。

**类别标记识别与标题提取分开处理。** 标题仍严格按v1：普通ATX标题和行首粗体前缀可取原文标题；`- **Definition**`不满足行首粗体标题条件，因此title仍是null，不悄悄增加去列表标记提取标题的规则。合成示例`### Ex: 常数函数`则是example，title保留为原文 `Ex: 常数函数`。

## 4. 证明请求优先识别为范围外题目

补充v1的proof判定，先区分“要求给出证明”与“已经在进行证明”：

| 原文用途 | 标注 | 依据 |
| --- | --- | --- |
| 题目要求、待证目标，如“请证明……”“求证……”或“证明：级数……收敛。” | `other/out_of_scope` | 这是要求完成任务，没有给出论证过程 |
| 明确引入证明，并给出推理、构造、反证、计算或归结等论证内容 | `proof`，reason为null | 如“证明：由比较判别法……因此收敛。” |
| 明确独立的定理与证明同处一个列表项/块 | `uncertain/mixed_roles` | 先完成请求判定，再处理真实角色混合 |
| 现有输入确实不足以区分题目要求或证明正文 | `uncertain/insufficient_context` | 只在原文证据不足时使用，不替规范缺口兜底 |

判别仅使用本块及输入片段内上下文；不能查看未放入模型输入的后文来提供标签依据。`证明：`前缀本身不保证proof；同样，不能因为步骤少或证明错误就当成题目。数学正确性仍不评判、不改写。
若“求证……”是在代码、引用或普通句子中被提及，仍按原v1的代码/引用/正文规则处理，不以关键词覆盖整块。
`题目/习题/解答`显式标记仍属于other；该类别不自动传播到相邻公式或没有该标记的后续块。独立且明确的Proof段仍可为proof。

## 5. 判定次序与标题/保真边界

当前顺序为：保留代码/引用等原有边界 → 识别真实的题目请求及范围外结构 → 检查独立角色是否混合 → 使用完整标记或新缩写定类别 → 普通标题heading → 无证据则body。
v1关于标题原文、reason枚举、一块一项、编号顺序、1–8块/片段、2000字符/块与6000字符/片段上限继续适用；字符数不等于Qwen token预算。
不沿用前块角色、不补标题、不改公式或代码。新版也不会把所有推导自动识别为proof；没有显式标记的推导仍可为body。
后续完整提示必须同时包含v1沿用规则和本页覆盖条款，绑定版本及摘要，不能只改schema版本号就声称提示已实现新版。当前尚未交付或运行完整模型推理入口。
