# 主线验收路线

本文件替代旧十周逐课计划。**下一任务以 [current-work.md](current-work.md) 为准。**
已完成的基础学习、作业验证和项目模块不重做；没有固定日期或“每篇教程下一小步”。

1. 模型与运行基础（已验收）：Transformer、共享权重、训练/评估、恢复、生成与KV Cache。
   数学与接口按需查 [运行参考](runtime-reference.md)，不再迁移一遍作业代码。
2. Tokenizer与pilot数据闭环（已验收）：16000词表保存/重载，使用同一版本编码固定三集合；
   全部1000篇磁盘读回与正文/EOS/LF一致，参见 [Token编码验收](token-encoding-guide.md)。
3. 33M短验证（已验收）：context512/batch2/BF16，100步数值正常、完整valid loss下降；
   50步保存恢复与连续100步的权重/优化器/采样器/RNG完全一致，见 [33M短验证](33m-short-validation.md)。
4. 实际云端资源验证：约500步测速，根据真实设备、精度和价格确定预算；不预设费用保证。
5. 正式语料与预训练：用预算明确、来源可追溯的语料，不把小语料重复计数当正式规模；
   首轮计划1亿tokens，是否扩到2亿由验证走势/语料/预算决定。
6. 评测与展示：真实曲线、固定prompt样例、复现说明和模型卡；
   Character/BPE、位置编码、缓存等消融在主闭环成功后按预算做。
7. 独立0.6B LoRA：自己的基座权重/tokenizer、SFT与多轮服务、微调前后受控评测；
   不用它替代33M主线，也不把33M模型或16K BPE直接套到0.6B基座。

## 工作节奏

每次只推进一个可验收产物：实现/运行 → 测试 → 解释 → 用户Git提交。
已有工具可以复用；只修复真正阻塞当前验收的问题，不新增“顺便完善”的支线。
数据来源、格式、划分和数值检查保留，完整维基渲染、全站解析和批量审批平台不在当前范围。
